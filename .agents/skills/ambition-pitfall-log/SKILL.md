# Ambition 雷点日志与施工守则

你在 `D:/rust/ambition`（Ambition 项目）工作。本 skill 约束三件事：**记坑、记进度、抢锁**。

## 1. 开工前（必读）

1. `read PITFALLS.md` —— 先看已记录的错误与雷点，**同样的坑不允许踩第二次**；
2. `read PROGRESS.md` —— 确认当前阶段（`MVP_STAGE:` 行）与上一轮代码评估的改进建议；
3. 抢施工锁：`bash scripts/task_lock.sh acquire`
   - 成功 → 在锁目录写心跳（脚本自动），任务结束必须 `release`（脚本带 trap）；
   - 失败 → 说明已有 pi 任务在施工本项目：**不要并行动手**，输出“等待中”并结束，等定时任务下一轮接手。

## 2. 遇到错误/雷点时（记录规则）

把**已解决**的坑追加到 `PITFALLS.md`（未解决的先标注 `- [ ]`）。每条必须五要素：

| 字段 | 说明 |
|---|---|
| ID | `P-序号`（接着已有最大号） |
| 症状 | 报错原文/异常行为（截关键行） |
| 根因 | 为什么会这样（一句话） |
| 解决 | 实际改了什么 |
| 预防 | 下次怎么避免（最好写成钩子/脚本/规范） |

收录范围（都要记）：编译/测试/钳制失败、**库的隐性行为**（如 ratatui 宽字符续格、sqlx 定时器）、工具链坑（PATH/编码/换行/Windows 特性）、流程坑（fmt 改文本导致编辑锚点失配等）、钩子绕过尝试。

**防重复**：写之前先 grep 已有条目；同一根因 → 更新原条目（改写/补充案例），不新开。

## 3. 完成一个部分时（进度 + 评估）

1. 更新 `PROGRESS.md`：
   - 阶段/子项状态勾选；
   - 「进度日志」追加一条（做了什么、测试数、提交 hash）；
   - **代码评估**（必写，四段）：
     - 代码质量（测试/静态检查/命名/文档同步）
     - 实际使用（用户能不能真跑起来、边界在哪）
     - 代码耦合度（依赖方向、是否有环、旁路解耦是否到位）
     - 鲁棒性（错误路径/降级/原子性/锁与并发）
   - 「改进建议」更新：已修的划掉/移入完成，新发现的追加；
2. 提交必须过七步钩子（见 docs/01-engineering §3）；
3. `bash scripts/task_lock.sh release`。

## 4. 红线

- 绝不为过钩子而放松钩子（禁删检查、禁加 allow）；
- 契约变更先改 docs 分册再改码（01-engineering §4 文档先行）；
- 预留参数不进签名（写 TODO 注释）。
